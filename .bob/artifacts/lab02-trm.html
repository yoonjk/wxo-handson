2. 호출 실행 흐름 비교 (Agent → TRM → TR)
🔴 Python Tool — unit_convert (Cold Start)
사용자 → math_agent
"100km는 몇 마일?"
wxo-server-worker (Celery)
Tool 선택 결정: unit_convert
TRM_BASE_URL → tools-runtime-manager :8080
unit_convert 실행 요청
MinIO에서 unit_convert.py 다운로드
매 호출마다 발생
tools-runtime :8000 → subprocess 생성
python unit_convert.py 실행
DISABLE_SUBPROCESS_EXECUTION=false
Python 인터프리터 초기화 + import
cold start 비용 (수백 ms)
unit_convert(100, "km", "mile") 실행
→ "100 km = 62.1371 mile"
프로세스 종료
결과 반환 후 즉시 소멸 (stateless)
Agent → 사용자 응답
TOOL_TIMEOUT: 300s 내
⚠️ 다음 호출에서도 동일하게 subprocess 새로 생성됨
🔵 Python Toolkit — math_toolkit (Warm)
사용자 → math_agent
"144의 제곱근은?"
wxo-server-worker (Celery)
Tool 선택 결정: square_root
TRM_BASE_URL → tools-runtime-manager :8080
math_toolkit / square_root 실행 요청
tools-runtime :8000 — 프로세스 이미 상주 중
tier=small 전용 자원으로 기동 유지
tools-runtime-data (shared-data) 에서 로드됨
상주 프로세스에 함수 호출 메시지 전달
subprocess 생성 없음 — IPC only
square_root(144) 실행
→ "√144 = 12.0" (수십 ms)
프로세스 유지 (종료 안 함)
다음 호출도 즉시 응답 가능 (stateful 가능)
Agent → 사용자 응답
TOOL_TIMEOUT: 300s 내
✅ 다음 호출(power, square_root)도 동일 프로세스에서 즉시 처리

5. 성능 관점 요약
항목 🔴 Python Tool (unit_convert) 🔵 Python Toolkit (math_toolkit)
TRM 처리 호출마다 MinIO fetch → subprocess spawn 등록 시 1회 배포 → 프로세스 상주
Cold Start 매 호출마다 발생 최초 1회만
Warm 호출 지연 수백 ms ~ 수 초 (Python 초기화 포함) 수십 ms (IPC 메시지만)
메모리 요청 시 생성, 완료 후 해제 tier=small 전용 메모리 상시 점유
상태 유지 Stateless Stateful 가능
적합한 사용 단순 변환 함수, 빠른 프로토타이핑 초기화 비용 있는 로직, 반복 호출 많은 경우
