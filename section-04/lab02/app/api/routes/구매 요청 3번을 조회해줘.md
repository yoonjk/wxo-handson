# Purchase Approval A2A Agent 최종 설정 가이드

이 문서는 기존 FastAPI 구매 승인 애플리케이션에 Google A2A 0.3.0 엔드포인트를 추가하고, watsonx Orchestrate에서 외부 에이전트로 등록하는 절차입니다.

## 1. 최종 엔드포인트

애플리케이션이 `ROOT_PATH=/purchase`로 Nginx 뒤에서 실행되는 기준입니다.

| 용도 | URL | HTTP |
|---|---|---|
| Agent Card 조회 | `http://nexweb.ddnsgeek.com/purchase/.well-known/agent-card.json` | GET |
| Orchestrate A2A 호출 | `http://nexweb.ddnsgeek.com/purchase/a2a` | POST |

중요한 점은 Orchestrate의 **Service instance URL**에는 Agent Card URL이 아니라 `/a2a` 호출 URL을 입력하는 것입니다.

## 2. 파일 배치

최종 `a2a.py`를 다음 위치에 배치합니다.

```text
app/
└── api/
    └── routes/
        └── a2a.py
```

`main.py`에는 다음 라우터 등록이 있어야 합니다.

```python
from app.api.routes.a2a import router as a2a_router

app.include_router(a2a_router, prefix="/purchase")
```

이미 `ROOT_PATH`를 별도 방식으로 처리하는 프로젝트라면 `/purchase`가 중복되지 않도록 현재 `main.py`의 라우터 구성에 맞춰 한 번만 적용합니다.

## 3. 목록 조회를 위한 Repository 변경

`app/repositories/purchase_repository.py`에 `list_all()`을 추가합니다.

```python
from app.models.purchase_request import PurchaseRequest


def list_all(self) -> list[PurchaseRequest]:
    """구매 승인 요청을 최신 ID 순서로 모두 조회합니다."""

    return (
        self.db.query(PurchaseRequest)
        .order_by(PurchaseRequest.id.desc())
        .all()
    )
```

클래스 내부에서는 다음과 같은 형태입니다.

```python
class PurchaseRepository:
    # 기존 메서드 생략

    def list_all(self) -> list[PurchaseRequest]:
        """구매 승인 요청 전체 목록을 조회합니다."""

        return (
            self.db.query(PurchaseRequest)
            .order_by(PurchaseRequest.id.desc())
            .all()
        )
```

## 4. 목록 조회를 위한 Service 변경

`app/services/purchase_service.py`에 다음 메서드를 추가합니다.

```python
from app.models.purchase_request import PurchaseRequest


class PurchaseService:
    # 기존 메서드 생략

    def list_all(self) -> list[PurchaseRequest]:
        """구매 승인 요청 전체 목록을 Repository에 위임합니다."""

        return self.repository.list_all()
```

이 변경이 없으면 A2A 소스의 목록 조회 분기에서 `AttributeError`가 발생합니다.

## 5. 환경변수 설정

DB 비밀번호와 A2A 토큰은 소스에 하드코딩하지 않고 `.env` 또는 운영 환경변수로 설정합니다.

```env
DB_HOST=nexweb.ddnsgeek.com
DB_PORT=13306
DB_USER=nexweb
DB_PASSWORD=<MySQL 비밀번호>
DB_NAME=demo

PUBLIC_API_URL=http://nexweb.ddnsgeek.com/purchase
A2A_BEARER_TOKEN=<Orchestrate connection에 입력한 동일한 토큰>

ROOT_PATH=/purchase
AUTO_CREATE_TABLES=false
```

`PUBLIC_API_URL`에는 `/a2a`를 포함하지 않습니다. 최종 Agent Card의 `url`은 코드가 자동으로 다음처럼 만듭니다.

```text
http://nexweb.ddnsgeek.com/purchase/a2a
```

## 6. Agent Card 확인

Agent Card는 반드시 GET으로 확인합니다.

```bash
curl -i \
  'http://nexweb.ddnsgeek.com/purchase/.well-known/agent-card.json'
```

정상 응답에서 다음 값을 확인합니다.

```json
{
  "protocolVersion": "0.3.0",
  "preferredTransport": "JSONRPC",
  "url": "http://nexweb.ddnsgeek.com/purchase/a2a"
}
```

Agent Card URL에 POST하면 안 됩니다. Agent Card에 POST하여 `405 Method Not Allowed`가 발생하는 것은 정상적인 HTTP 메서드 불일치입니다.

## 7. curl로 A2A 호출 확인

### 7.1 목록 조회

```bash
export A2A_BEARER_TOKEN='<설정한 토큰>'

curl -sS -i -X POST \
  'http://nexweb.ddnsgeek.com/purchase/a2a' \
  -H "Authorization: Bearer ${A2A_BEARER_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": "list-1",
    "method": "message/send",
    "params": {
      "message": {
        "kind": "message",
        "messageId": "list-message-1",
        "role": "user",
        "parts": [
          {
            "kind": "data",
            "data": {
              "action": "list_requests"
            }
          }
        ]
      }
    }
  }'
```

자연어도 지원합니다.

```json
{
  "kind": "text",
  "text": "구매 승인 요청 목록을 조회해줘"
}
```

정상 결과의 핵심 구조는 다음과 같습니다.

```json
{
  "jsonrpc": "2.0",
  "id": "list-1",
  "result": {
    "kind": "message",
    "role": "agent",
    "parts": [
      {
        "kind": "text",
        "text": "구매 승인 요청 목록 조회 결과입니다. 총 1건입니다."
      },
      {
        "kind": "data",
        "data": {
          "count": 1,
          "items": []
        }
      }
    ]
  }
}
```

목록 조회는 즉시 완료되는 동기 작업이므로 최종 `a2a.py`에서는 목록 조회에
대해 `Task`가 아니라 직접 `Message`를 반환합니다. A2A 0.3.0의
`message/send` 응답은 `Task` 또는 `Message`를 사용할 수 있습니다.

Task 응답을 사용하는 구현에서 `status.state`만 있고 `status.message`가
없으면 일부 Orchestrate 화면에서 A2A 호출은 성공했지만 다음과 같이 표시될
수 있습니다.

```text
LLM has responded with empty message. Please try again.
```

따라서 최종 응답 문장은 `history`뿐만 아니라 완료 Task의
`status.message.parts[].text`에도 넣어야 합니다. 최종 `a2a.py`에는 이 처리가
반영되어 있습니다.

### 7.2 구매 요청 생성

```bash
curl -sS -X POST \
  'http://nexweb.ddnsgeek.com/purchase/a2a' \
  -H "Authorization: Bearer ${A2A_BEARER_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": "create-1",
    "method": "message/send",
    "params": {
      "message": {
        "kind": "message",
        "messageId": "create-message-1",
        "role": "user",
        "parts": [
          {
            "kind": "data",
            "data": {
              "purchase_type": "NOTEBOOK",
              "requester": "홍길동",
              "total_amount": 150000,
              "reason": "노트북 구매"
            }
          }
        ]
      }
    }
  }'
```

### 7.3 승인 처리

```bash
curl -sS -X POST \
  'http://nexweb.ddnsgeek.com/purchase/a2a' \
  -H "Authorization: Bearer ${A2A_BEARER_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": "approve-1",
    "method": "message/send",
    "params": {
      "message": {
        "kind": "message",
        "messageId": "approve-message-1",
        "role": "user",
        "parts": [
          {
            "kind": "data",
            "data": {
              "request_id": 3,
              "approval": "APPROVED",

              "approval_comment": "구매 승인"
            }
          }
        ]
      }

  }'
```

### 7.4 특정 구매 요청 단건 조회

구조화된 A2A data part를 사용하는 경우에는 `request_id`만 전달합니다.

```json
{
  "jsonrpc": "2.0",
  "id": "get-1",
  "method": "message/send",
  "params": {
    "message": {
      "kind": "message",
      "messageId": "get-message-1",
      "role": "user",
      "parts": [
        {
          "kind": "data",
          "data": {
            "request_id": 3
          }
        }
      ]
    }
  }
}
```

Orchestrate 채팅에서는 다음처럼 입력할 수 있습니다.

```text
구매 요청 3번을 조회해줘
```

최종 소스는 `구매 요청 3번`, `구매 요청 번호 3`,
`purchase request 3`과 같은 표현에서 ID를 추출하여 단건 조회로 처리합니다.
단, `구매 승인 요청 목록을 조회해줘`처럼 특정 번호가 없는 요청은 전체 목록 조회로 처리합니다.

## 8. watsonx Orchestrate 등록

### 8.1 Connection

Connection의 A2A 설정은 다음과 같이 입력합니다.

| 항목 | 값 |
|---|---|
| Authentication type | `Bearer Token` |
| Server URL | `http://nexweb.ddnsgeek.com/purchase/a2a` |
| Bearer token | 서버의 `A2A_BEARER_TOKEN`과 동일한 값 |
| Credential type | Team credentials 또는 Member credentials |

Bearer Token 입력란에는 `Bearer ` 접두사를 붙이지 않고 토큰 값만 입력합니다.

```text
올바른 입력: qwer1234567890!
잘못된 입력: Bearer qwer1234567890!
```

### 8.2 External agent

AI Gateway의 Agent directory에서 **Add agent**를 선택합니다.

다음 값을 사용합니다.

| 항목 | 값 |
|---|---|
| Purpose | `Import for use and observability` |
| External protocol | `External agent via A2A protocol` |
| A2A protocol version | `0.3.0` |
| Service instance URL | `http://nexweb.ddnsgeek.com/purchase/a2a` |
| Display name | `purchase_approval_a2a_agent` |
| Connection | 앞에서 만든 A2A connection |

`/.well-known/agent-card.json`은 브라우저나 curl에서 Agent Card를 확인할 때만 사용합니다. Orchestrate의 Service instance URL에는 `/a2a`를 입력합니다.

## 9. Orchestrate Agent에서 사용

External agent가 Agent directory에 등록되면 Orchestrate Agent Builder에서 `Agents` 탭으로 이동하여 등록된 `purchase_approval_a2a_agent`를 추가합니다.

별도의 `Collaborators` 메뉴가 보이지 않는 화면에서는 다음 흐름을 사용합니다.

```text
Agent Builder
  → Agents 탭
  → 등록된 external A2A agent 선택
  → Add
  → Save
```

Agent instruction에는 다음과 같이 명시하는 것이 좋습니다.

```text
구매 승인 요청과 관련된 작업은 purchase_approval_a2a_agent에게 위임한다.
구매 승인 요청 목록 조회 시 action=list_requests를 사용한다.
새 구매 요청 생성 시 purchase_type, requester, total_amount, reason을 전달한다.
승인 또는 반려 시 request_id, approval, approver_role, approval_comment를 전달한다.
A2A 응답의 artifacts에 있는 data를 사용자에게 자연어로 설명한다.
```

## 10. 로그 및 오류 확인

HTTP 200이 항상 업무 성공을 의미하지는 않습니다. JSON-RPC 오류는 HTTP 200 응답의 `error` 필드에 포함될 수 있습니다.

```json
{
  "jsonrpc": "2.0",
  "id": "list-1",
  "error": {
    "code": -32602,
    "message": "total_amount is required when creating a purchase request"
  }
}
```

주요 상태 코드는 다음과 같습니다.

| 상태 | 원인 |
|---|---|
| `401` | Authorization 헤더 누락, 토큰 불일치, Bearer 형식 오류 |
| `405` | Agent Card URL에 POST 수행 또는 A2A URL에 GET 수행 |
| `200 + error -32601` | 지원하지 않는 JSON-RPC method |
| `200 + error -32602` | 입력 데이터 누락 또는 형식 오류 |
| `200 + error -32004` | 존재하지 않는 구매 요청 ID |
| `200 + error -32009` | 허용되지 않는 승인 상태 전이 |

## 11. 배포 후 재시작

Docker Compose를 사용하는 경우 소스와 환경변수를 반영한 뒤 재빌드합니다.

```bash
docker compose up -d --build --force-recreate
```

컨테이너 로그를 확인합니다.

```bash
docker compose logs -f purchase-api
```

정상 호출 시 다음과 같은 로그가 출력되어야 합니다.

```text
POST /purchase/a2a HTTP/1.1 200 OK
```

단, 최종 성공 여부는 HTTP 상태가 아니라 JSON 응답의 `result` 또는 `error` 필드로 확인해야 합니다.

## 12. 보안 주의사항

현재 예제는 고정 Bearer Token 비교 방식입니다. 운영환경에서는 다음을 적용해야 합니다.

* 토큰을 Git 저장소와 소스 코드에 저장하지 않습니다.
* 이미 외부에 노출된 토큰은 폐기하고 새 토큰으로 교체합니다.
* Keycloak JWKS/OIDC 검증으로 전환합니다.
* issuer, audience, expiration, scope를 검증합니다.
* Nginx에서 HTTPS를 사용합니다.
* MySQL 포트는 필요한 네트워크에서만 접근하도록 제한합니다.
